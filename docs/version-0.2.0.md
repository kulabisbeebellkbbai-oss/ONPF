# ONPF 0.2.0 Community Garden update

This branch implements the walkthrough requests CG001-CG016 in [the change log](public-source-release.md). Source commit `6238df65804ced64242b462267b74fac03a7688b` was installed and verified on the existing AWS installation on 2026-10-02. See [deployment evidence](public-source-release.md). Immutable Community Garden release 1 was preserved.

## Changes

- Proposal saves record incorporation automatically; owner decisions freeze selected proposal wording and linked response revisions. Older decision links are labeled when their original wording could only be captured during migration. Response coverage and selection views use stable references, question context, groups, search, filter, and sort controls. (CG001, CG004, CG006, CG007)
- Unlimited numbered clarification rounds preserve issued questions, provenance, recipients, answers, and explicit deferrals. Pending questions block candidate preparation; owners acknowledge explained deferrals. New rounds stale earlier candidates. A collapsible guide exposes each workflow step and round progress. (CG005, CG008)
- Question, proposal, decision, and document-section forms offer explicit AI draft buttons. Each use requires consent to send the selected private evidence to the configured OpenAI-compatible endpoint. Drafts populate editable fields and never save or approve anything automatically. See [provider setup](ai-drafting.md). (CG002, CG003, CG008)
- The administrator supplies a shared AI provider. Production reads its credential from a protected file with rotation support; configuration survives installer reconfiguration. Per-user and installation request limits, one concurrent draft per server process, stale-form checks, safe provider failures, and a database-free administrator diagnostic complete the user-triggered drafting scope. Autonomous multi-step work and per-user provider accounts are outside this release.
- Per-project viewers, account-level creation rights, and a scoped management console enforce access on the server. (CG010-CG012)
- Private site-permission versions retain issuer, dates, scope, conditions, attachment, revocations, and copy distribution. Readiness and candidate approval distinguish design decisions from evidence that permission was filed. (CG009)
- Owners can publish frozen public project versions with actual approval status, recorded operating status, and filed permission-evidence status at publication. The public page also shows current evidence status. Visitors can browse versions and download all seven documents as Markdown, ODT, and printable HTML, plus an editable ZIP. Private project evidence is excluded. (CG014)
- Projects can create additional recipe cards, pantry wall posters, and other media from templates, attach an existing PDF/ODT/PNG/JPEG, and download printable or editable drafts. Editors record rights and can offer an item for owner publication review. The owner checks each item for the exact public version; unchecked items remain private. These media are separate from the seven-document design approval. (CG016)
- The public hero link opens a Community Garden walkthrough and finishes at the contact form with the new-workspace request type selected. The release print view gives budget notes more room, avoids forced blank pages, and explains clean browser PDF settings. (CG013, CG015)
- Candidate preparation flags draft-stage claims inside document text for human review. It does not rewrite previously approved wording.

## Compatibility and review

The live SQLite database upgrades by applying migrations 010-017 on first 0.2.0 startup. Migration 017 adds runtime AI attempt counters, which are excluded from logical backups and reset on restore. Back up and test an independent copy before a production upgrade. Private archives remain tied to their exact application version and migration sequence: restore a 0.1.0 archive with its matching source, then let 0.2.0 migrate the restored database. Preserve the original archive until a 0.2.0 backup and recovery rehearsal succeed.

The new public publication ZIP is a frozen editable source with manifest hashes; ONPF's existing ZIP import command currently accepts approved-release packages only. Publication ZIPs can be edited and reused manually. The AI adapter is tested over real HTTP against a loopback test provider, including on the installed Linux environment. Linux credential mode and symlink checks passed using synthetic credentials. A real Ollama or provider-gateway account handshake and production privacy/retention settings still require administrator setup; production AI remains disabled. The AWS rollout and backup recovery passed as recorded in [deployment evidence](public-source-release.md). No real Community Garden publication was created. Future upgrades should follow the [existing-instance update runbook](aws-community-garden-update.md) and the exact release identity in the delivery's `START-HERE.md`.

Uploaded PDF and ODT attachments are size and file-type checked, but their active features are not sanitized. Review attached files before offering them for publication.
