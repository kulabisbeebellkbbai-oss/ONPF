Community Garden: a project walkthrough

Follow how a community garden idea moves through ONPF. These slides describe the workflow using public example themes; they contain no private participant responses or internal owner rationale.

01 / Start

Start with a local idea

Create a program workspace, describe the community purpose and local context, then select the relevant activity modules. Assign decision owners, facilitators, and viewers by project.

02 / Ask

Invite several perspectives

Review the initial inquiry questions, issue a frozen batch, and invite the people who should answer. Responses can be entered online, from paper, or after a meeting. The original response and later corrections remain traceable.

03 / Refine

Turn input into proposals

Find and group responses, select source evidence, and write or request an editable proposal draft. Saving a proposal records its source links. A generated draft stays unsaved until a person reviews and saves it.

04 / Clarify

Ask again when details are missing

Issue a numbered clarification round after proposals, after decisions, or during document review. Each question keeps its source and reason. Answers and explicit deferrals stay in the project record; later rounds can follow.

05 / Decide

Owners make design choices

Decision owners review linked proposal evidence and record an outcome and rationale. The evidence can be reused without selecting the same responses again. Recording a decision does not approve documents or verify site permission.

06 / Draft

Build the document set

Draft the program overview, delivery and volunteer guides, resource budget, reusable session plan, feedback tools, and adoption guide. Create additional recipe cards, pantry posters, or other media from templates and attach existing files when useful. Unknown costs and unresolved operating details remain labeled for review.

07 / Review

Check the exact version

Review response coverage, public wording, selected materials, and separate operating-permission evidence. Owners can prepare an exact-content candidate and explicitly approve it. Design approval never stands in for permission to operate.

08 / Share

Publish a reusable public copy

An owner can review and publish a frozen public project version with its real approval and operating status. Visitors can browse public documents, print them, or download an editable package. Private input and permission attachments are excluded.

09 / Your project

Request a workspace of your own

Tell the administrator about the program or project you want to develop. The request type is selected for you, and you can edit the form before choosing Send.
